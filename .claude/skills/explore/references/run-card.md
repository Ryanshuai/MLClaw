# run card：一次实验的条件怎么记下来 —— MLClaw 盖住了哪几样

`SKILL.md` 的「实验记录标准」指到这里。**跑之前写卡，跑完只允许追加结果。**

‼️ **在 MLClaw 里这张卡就是 `run.json`，不要另建一套。** 一条臂是 `/train-run` 或
`/eval-run` 发起的普通 run，它的 `run.json` + `config_snapshot.json` + `sources.json`
+ `code_dirty.patch` 已经是这张卡。源项目的 `scripts/runcard.py` 是在没有 MLClaw 的
情况下重新实现了这一层 —— 两边独立收敛到同一组字段，这份文件的价值现在是**指出
MLClaw 还差哪几样**，而不是再造一次。

下面七样逐条对照。‼️ **三个 ⚠️ 是真缺口，开臂之前自己补，不要假设 MLClaw 拦得住。**

‼️ 正文只留判断（为什么必须记、四条硬规则的一句话版）；**这里是格式与实测教训的全文**。

---


‼️ **一次实验，条件只活在聊天记录里，那它就不是实验，是轶事。**
一旦出现多臂、多轮、而且**多种先后次序**，「这个数为什么和那个不一样」就没法凭记忆回答了 ——
而那恰恰是辩论 ① 要裁的问题。**没有东西可引的辩论，产出的是意见。**

规矩：**每个 run 一张卡，跑之前写，跑完只允许追加结果。**
工具是 `scripts/runcard.py`（`declare` / `event` / `attach` / `check` / `codediff`）。

#### 卡上必须有的七样，以及为什么命令行不够

| 记什么 | MLClaw | 为什么不能只记命令行 |
|---|---|---|
| **解析后的完整 config** | ✅ `config_snapshot.json` | 默认值会漂。本项目丢过一个结果：eval 脚本默认 40000 点而权重是 145000 训的，唯一症状是一个坏数字。**命令行里没写的 flag，等于什么都没记** |
| **代码身份，含未提交改动** | ✅ `code_snapshot.py` —— `origin_commit` + `code_dirty.patch`，**未跟踪文件计入**，`reproducible` 说得清 | ‼️ 一轮实验在飞的时候没人提交，**git sha 指向一棵不存在的树**。要哈希真正跑的那些字节 |
| **数据身份，不是路径** | ✅ `datasets/<id>@<snapshot>` + `sources.json` | 路径会被复用，内容会被重生成。今天的 `box9dof/` 是 levelled 导出、npz 格式变了 110 倍，目录名一模一样 |
| **环境** | ✅ run.json 的 env 快照 | 编译产物是 arch 相关的：sm_90 的 kernel 在 sm_89 上装不进去。「这儿能跑那儿不能」要可回答 |
| **可比性指纹** | ⚠️ **部分** —— `mode` + `scope` + `list_runs.py --comparable` 比的是数据和口径，**不含度量脚本本身**。换了度量脚本的两个 run 在 MLClaw 眼里仍然可比 | 见下 |
| **中断/重启历史** | ⚠️ **部分** —— `pool.py` 记 `preempted`/`crashed`，`workload`（declare）对 `scope`（实际）能露出差异，但没有"这 20 个 epoch 是四段"的分段史。‼️ 读它的 `/train-triage` **还没建** | 抢占式机器上「20 个 epoch」可能是四次被打断的尝试。**epoch 数不是训练史** |
| **没跑什么** | ⚠️ **没有** —— 数据侧有 `census.complete: false`，run 侧没有对应物。‼️ 砍掉的臂、抽样、top-N 全靠你在 `graph.json` 里留卡 | 静默截断（top-N、抽样、砍掉的臂）读起来像全覆盖 |

#### 四条硬规则

**1. ‼️ delta 要算出来，不是描述出来。**
MLClaw 算了 —— `lineage.variation_summary` 是 fork 相对 base 的 `runtime_params` 实差。
‼️ **但它不断言这个差等于你声明的那个。** 源项目的 `check` 会做这条断言，实测拦下过
「声明 `[iou_aware_cls]`，实际 `[dn_rot_noise_deg, iou_aware_cls]`」。在 MLClaw 里
这一步是你的：开臂前把 `variation_summary` 和卡上的 `delta` 对一眼。
（原理：`check` 把两张卡的 config 做差，断言结果等于 `declared_delta`。）
散文说「这一臂加了 CDN」，config diff 说这一臂**还顺带吃到了上周三挪过的一个默认值**。
两者只有一个是可核的。实测拦下过：声明 `[iou_aware_cls]`，实际
`[dn_rot_noise_deg, iou_aware_cls]`。
**差超过一个 key 就不是受控实验，任何结果都不能归因到其中任何一个。**

**2. ‼️ `parent` 不是 `warm_start_from`。** MLClaw 分开了：`lineage.fork_of` 是配置来源，
`lineage.parents` 是消费的产物，而**卡上的 `parent` 是归因基线**，三个都不一样。

两种关系，混淆是真错误：一个臂可以从 run X 热启动，而它正确的对照基线是 run Y。
`parent` = 拿谁读它，`warm_start_from` = 权重从哪来。**没有 parent 的 run 无法归因。**

**3. ‼️ 可比性指纹 = hash(数据身份 + 度量脚本 + 门限)。**
指纹不同的两张卡**不许比**，`check` 直接拒。
‼️ **MLClaw 这条只做到一半**：`list_runs.py --comparable` 覆盖数据身份和 `scope`，
**不覆盖度量脚本和门限**。`stages/exploration/config.json -> fingerprint` 是给这条留的
位置，填了也还没有东西核它 —— 换度量脚本的那一刻，自己作废旧曲线。
这是两条本项目用钱换来的规矩的机器可执行版：「换了度量旧曲线就作废」和
「跨源对比要同口径，否则量到的是口径」。**以前靠记得，也就是没有执行。**

**4. ‼️ 存字节，不只存哈希 —— 而且别考虑存储成本。**
‼️ **MLClaw 存的是 patch，不是 tarball**，复现契约是 `git checkout <sha> && git apply`。
两者不等价：patch 依赖那个 commit 还在。force-push、删分支、GC 之后 `checkout` 会失败，
而 tarball 不会。`/repro` 的 `not_reproducible`（某条轴 `gone`）就是这个失败的名字 ——
它会**说出来**，但说出来不等于救得回。长命的臂考虑另外留一份字节。

哈希只回答「这两次不一样」，**只有副本能回答「哪里不一样」**，而六周后需要的是后者
（那时工作区早变了，要看的偏偏是变之前那次）。`codediff` 从两个 tarball 各自重建，
**当前工作区完全无关**。
一个臂的 GPU 时间是十几美元，快照是它的零头；**存储从来不该出现在这个决策里，
拿不准就多存**。实测：99 个文件 414 KB —— 不只 `.py`，shell launcher（一半超参实际住在
`train_anyware_9dof.sh` 里）、CUDA 源、lockfile、config 全都要。

‼️ **快照的文件清单要走文件系统遍历，不要走 git。** 这条改过两次，两次都是花钱买的：

第一版用 `git ls-files`（只列 tracked），实测 59 vs 63，漏掉的四个里包含 `models/denoising9d.py`
—— **被测技巧的全部实现**，因为一轮在飞时没人提交。于是改成 `git ls-files -co --exclude-standard`。

**第二版更糟，而且它在每一台机器上都错。** 训练机是 `rsync --exclude '.git'` 传上去的，
**根本没有 `.git`**，所以 git 在**每一台真正跑过实验的机器上**列出零个文件。实测 2026-08-14 六台：
`worktree_sha = e3b0c44298fc1c14`（空字符串的 SHA-256）、`code_snapshot.tar.gz` = 63 字节空 tar。
`check` 拿两个空哈希互比、报告 **"same code"** —— 它存在的唯一理由就是拦住这句话。

#### ‼️ 记录层自己会坏，而且坏法比实验的坏法更阴

一轮下来，我在**记录代码**里踩的坑比在模型代码里多。四种，都不报错：

| 坏法 | 症状 | 为什么危险 |
|---|---|---|
| **枚举出空集** | 哈希是 `sha256("")`，每个 run 都一致 | 守卫报出**它专门要排除的那个结论**。橡皮章比没有章更坏，因为章会被信 |
| **绝对路径进摘要** | 同样的字节在 `/home/shuai` 和 `/home/ubuntu` 下哈希不同 | 假阳性。读起来像"发现了代码差异"，会派人去找一个不存在的差异 |
| **中途修工具** | 修 `_sha_files` 顺带把工具产出的**每一个**哈希重新定了基；再叠上早于某次字段拆分的旧卡片 | `check` 报 "DATA DIFFERS -- 下游全部不可比"，而那份 manifest 在六台机上 md5 完全相同。**会因自己版本漂移而报警的守卫，是人学会忽略的守卫** |
| **分页当成全量** | `instance list` 每页 10 条，13 台机器时少 3 台 | 舰队视图把**基线**弄丢了，而截断的列表和完整的列表长得一模一样 |

对策，四条都要：

1. **空集是 bug，不是身份。** 文件数低于阈值直接 `SystemExit`，不许写出一张"哈希了虚无"的卡。
2. **摘要只吃内容**；名字要参与身份时吃**仓库相对路径**（改名要可见、整棵树搬走不可见）。
3. **工具改了，就用同一个版本把所有卡片的派生字段重推一遍**（原值留在 `superseded`，
   只重推**身份**，绝不碰 `result` / `purpose`）。先逐字节核底层文件真的相同，**再**统一记账 ——
   顺序反了就是拿统一记账掩盖真差异。
4. **任何"列出全部 X"的云 API 调用都要处理 `next_page_token`**，并且包一层，不要在各处直接调。

#### ‼️ 一个完全正确的测试，可以给出完全错误的信心

比「测试空过」更阴的一种：**测试对了，而它验的那一半不是承重的那一半。**

`tests/test_one_to_one.py` 把 F1 的算术钉得无可指摘 —— repeat 5 在 G=51 剩 1 个负样本、G=52 剩 0，
repeat 2 的零点在 128，而且是用 spy 读**真实 matcher** 的 mask，不是重实现一遍。它一条都没错，
文件头还写着「这些断言很便宜，而且是整轮站立的地板」。

**地板有两块**：算术那块钉住了，**「真实数据的 G 会不会到 52」那块根本没碰** ——
因为测试用 `_batch(n_gt)` 自己构造 G，所以真实语料的 G 是 25 还是 250，它都全绿。

规矩：**给一个机理写测试时，把它的输入分布也写成一条断言，并且用真实语料**。
形如 `assert (G >= 52).mean() > 0.2, "F1 的前提在这份语料上不成立"` —— 它会在起机器之前就红，
而不是在十三台机器跑了六小时之后才由结果告诉你。
**「公式对不对」和「公式的输入落在哪个区间」是两个命题，测了前者不算测了后者。**

#### ‼️ 给这些坑写的测试也会空过

给上面第一条写完回归测试，11 绿；把旧实现注回去只有 6 红。去看那 5 条为什么没红 ——
其中两条是**空对空过的**：老实现枚举零个文件，两边都是 `sha256("")`，"相等"成立，
**而成立的理由正是这个测试要抓的故障**。加了内建对照（先断言 `n_behaviour_files > 20` 再比哈希）之后 8 红。

**这就是 Stage 6 那条「判据会自我选择」用在测试上** —— 原话说的是指标，同一条对测试一样成立：
**判据的失败模式满足了判据自己。**
所以给记录层写测试，必须**双向验**：对修好的实现全绿，对原来那个坏实现**要红，而且要数红了几条**，
红得比预期少就去看少的那几条是不是空过。

#### 辩论要引 run id

⑤ 和 ① 的裁决记录里，每条主张和每个数字都要能指到一个 run id。
**指不到的主张不能进裁决表** —— 下一轮没人能重新检验它。

➜ 落点：run card 跟着 run 的输出目录走（和 `findings.json` 同理，它要被脚本读和 diff）；
裁决和提案照旧写进 `model_design.md`。
